# 통합과학 · AI 디지털교과서

고등학교 **통합과학1·2**(2022 개정)를 위한 탐구형 AI 디지털교과서입니다.
학생이 개념을 읽기만 하는 자료가 아니라, **예측 → 유도 → 시뮬레이션 → 평가 → 성찰**을
스스로 밟아가는 활동으로 구성되며, AI·디지털 도구가 *참여를 가능하게 하는 수업 조건*이 되도록 설계합니다.

**서버(백엔드)가 없는 단일 정적 파일**들이라 GitHub Pages에 그대로 올리면 동작합니다.
사이트 URL: `https://yurowa90.github.io/biology/`

> 🔑 **API 키·비밀값이 전혀 필요 없습니다.** 서술형·수행과제 피드백(자가 점검·예시 답안·자기평가)은 모두 학생 브라우저 안에서 만들어지고
> 어떤 AI 서비스도 호출하지 않습니다. 쓰는 데이터(NOAA ONI, Open-Meteo 해수면 온도)도 키가 필요 없는 공개 자료입니다.

### 목차·성취기준 소스

- 목차 뼈대는 **비상교육 「통합과학1·2」(2022 개정)** 를 기준으로 합니다.
- 활동·예시·탐구 소재는 **동아·미래엔·지학사·천재교육** 교과서를 교차 참고합니다(다음 단계에서 반영).
- 성취기준은 확인된 코드만 표기하고, 미확정 소단원은 홈에서 **"성취기준 확인 필요 · 비상 교과서 대조 예정"** 으로 남깁니다.
- 활동 데이터에는 출처(`sources`) 필드를 두어, 교차 참고한 출판사를 활동별로 기록할 수 있게 해 두었습니다(현재 비어 있음).

### 활동 유형 6종 (설계 프레임워크 매핑)

`개념`(지식구성 기초) · `시뮬레이션`(맥락·하이테크) · `PBL`(문제해결·프로젝트형) ·
`GRASPS`(수행과제) · `형성평가`(과정중심평가) · `성찰`(메타인지·하이터치)

> 이 교과서의 설계 원리(연수: AI·디지털 기반 교육혁신 선도교사): ① 맥락(실생활 연결) ② 지식구성(능동 탐구·성찰)
> ③ 상호작용·협력(모둠·토론) ④ 맞춤교육(개별화·데이터). **하이터치(관계·정서·고차사고) × 하이테크(AI 진단·시각화·시뮬레이션·자동 피드백)** 의 균형,
> 그리고 진단(사전) → 형성평가·즉각 피드백 → 성찰(KWL) → 교사 대시보드(데이터·직관 균형)의 과정중심평가–성찰 연계를 지향합니다.
> **GRASPS 활동**은 앞으로 만들 때 슬롯별 독립 생성이 아니라 Role↔Audience↔Situation을 한 세트로 함께 생성하고 Goal·Product 파생,
> Standards는 마지막 도출, 청중 근접성 축으로 3개 번들을 분산하는 원칙을 따릅니다(홈의 GRASPS 카드에 메모).

## 엘니뇨·라니냐 탐구 워크북 (`activities/enso.html`)

통합과학2 Ⅴ-2 기후 변화와 지구 환경 · 성취기준 **[10통과2-02-03]**. 연수 교안의 "Gemini 웹앱 시뮬레이터를 활용한
엘니뇨 탐구" 수업을 효소 워크북과 같은 8단계 구조로 옮기고, 실제 관측 데이터를 붙였습니다.

| # | 단계 | 내용 |
|---|------|------|
| 01 | 예측·진단 | 채점 안 하는 예측 3문항 + KWL의 K·W |
| 02 | 개념 | 무역풍·용승·수온약층·워커 순환, 엘니뇨·라니냐, ONI 판정 기준, 지구온난화와의 관계 |

### 데이터 출처와 갱신 방식

| 데이터 | 출처 | 방식 |
|--------|------|------|
| ONI (월별 3개월 이동평균 Niño3.4 편차) | NOAA CPC `oni.ascii.txt` | **빌드 시점 수집**: 배포 워크플로가 `node scripts/fetch-oni.mjs --inject activities/enso.html` 로 받아 `data/oni.json`과 페이지 내장 스냅샷을 채운 뒤 배포(커밋 없음). 매주 월요일 06:47(KST) 재배포 |

로컬(`file://`)에서는 ①을 건너뜁니다.

- 저장소의 `data/oni.json`은 현재 **자리표시(pending)** 입니다. 작업 환경에서 NOAA 접속이 막혀 있어 실제 값을 넣지 않았고, 값을 지어내지도 않았습니다.
  배포된 사이트에는 빌드 때 실제 값이 들어갑니다. 저장소 스냅샷도 채우려면 **Actions → Refresh ONI snapshot → Run workflow**를 한 번 누르거나,
  인터넷이 되는 PC에서 `node scripts/fetch-oni.mjs --inject activities/enso.html` 을 실행해 커밋하세요.
- 수집에 실패해도 배포는 멈추지 않습니다(스크립트가 경고만 남기고 기존 파일 유지). 검증: 600행 이상, 연도·계절·편차 범위 확인.
- ⚠️ **Settings → Pages → Build and deployment → Source 는 반드시 "GitHub Actions"** 여야 합니다. "Deploy from a branch"로 되어 있으면
  푸시마다 브랜치 원본 빌드("pages build and deployment")가 이 워크플로 배포와 동시에 돌아, 늦게 끝난 쪽이 게시됩니다.
  브랜치 원본이 이기면 자리표시 `data/oni.json`이 게시되어 화면에 "데이터 없음"이 뜹니다(활동은 정상 동작, 파일 불러오기 가능).
- GitHub `schedule`은 **저장소 기본 브랜치**에 있는 워크플로 파일로만 실행됩니다. 이 저장소의 기본 브랜치는 현재 `claude/bioscience-webapp-se292i` 입니다.
  기본 브랜치를 `main`으로 바꾸면 이 워크플로 파일도 `main`에 있어야 주간 갱신이 돕니다. (공개 저장소에서 60일간 활동이 없으면 GitHub이 예약 실행을 자동으로 멈춥니다.)
- API 키·비밀값은 쓰지 않습니다.

### GRASPS 피드백 — 자가 점검 · 자기평가 · 예시 개요 (키 불필요, 모두 로컬)

- **자가 점검**: 산출물을 키워드 루브릭으로 점검해 ✓(발견) / △(보완)과 안내 질문을 보여 줍니다. 공통 5항목(근거 수치·±0.5 ℃ 기준,
  메커니즘(무역풍·용승·수온약층), 지역별 영향, 청중 맞춤 제안, 출처)에 과제별로 대기 순환·강수, 불확실성 항목이 더해집니다.
  '작성 틀 넣기' 문구는 점검과 글자 수에서 뺍니다. 화면에 "키워드 기반 자동 점검 — 참고용이며 최종 평가는 선생님이 합니다"라고 표시합니다.
- **자기평가**: 선택한 과제의 평가 기준마다 학생이 충족/부분/보완을 고르고, 옆에 그 기준과 관련된 자동 점검 결과가 함께 보입니다.
  보고서에는 **학생 자기평가 + 자동 점검(키워드 기반) · 교사 확인 필요**로 기록됩니다(payload `grasps.review`).
- **예시 개요**: 직접 쓴 부분이 60자 이상일 때 열 수 있고, 열람 여부·시각이 보고서에 남습니다(`grasps.exemplarViewed`, `exemplarViewedAt`).
- 루브릭은 `GRASPS_CHECKS`, 기준별 연결은 `BUNDLES[].standards[].checks`, 예시 개요는 `GRASPS_EXEMPLAR` 에서 고칩니다.

## 효소반응속도 워크북 (라이브 활동) · 미카엘리스–멘텐

로켓방정식(치올콥스키 식) 학습 워크북을 **생명과학 맥락**으로 옮긴 탐구형 활동입니다.
효소·물질대사 단원의 핵심 정량식인 **미카엘리스–멘텐 반응속도식**을 중심으로, 학생이
예측 → 유도 → 개념 → 시뮬레이션 → 평가 → 서술형 → 보고서까지 스스로 밟아 갑니다.
파일 위치는 `activities/enzyme-kinetics.html` 이며, 홈(`index.html`)의 "통합과학1 ▸ 시스템과 상호작용 ▸ 생명 시스템"에서 링크됩니다.

## 8단계 흐름

| # | 단계 | 내용 |
|---|------|------|
| 01 | 예측 (PREDICT) | 채점하지 않는 직관 문항 — [S]를 높이면 v는? 효소 2배면 Vmax는? |
| 02 | 이론 유도 (THEORY) | E+S⇌ES→E+P 에서 정상상태 가정으로 `v = Vmax·[S]/(Km+[S])` 유도 (6단계 아코디언) |
| 03 | 회전수 kcat (TURNOVER) | `Vmax = kcat·[E]₀`, 촉매효율 kcat/Km, 낮은/높은 기질 농도에서의 거동 |
| 04 | 시뮬레이터 (SIMULATOR) | 효소 반응 애니메이션 + v–[S] 포화 곡선 ↔ 이중역수(Lineweaver–Burk) 그래프. Vmax·Km·[S]·억제제(경쟁적/비경쟁적) 슬라이더, 실시간 수치와 체크리스트 |
| 05 | 유도 확인 (CHECK) | 유도 각 단계를 확인하는 4지선다 4문항, 즉시 채점·해설 |
| 06 | 형성평가 (FORMATIVE) | 포화·효소농도·억제제·회전수 종합 4문항 |
| 07 | 서술형 · 자가 점검 | 서술형 2문항 + 키워드 루브릭 **자가 점검**(✓/△ + 안내 질문) + 예시 답안(60자 이상 작성 후 열람, 기록됨) |
| 08 | 최종 보고서 (SUBMIT) | 전체 답안·점수 정리 → 제출 / 인쇄(PDF) / 다운로드 |

원본 로켓 워크북과의 대응:

- 치올콥스키 식 유도 ↔ 미카엘리스–멘텐 식 유도
- 연소율 ṁ, 추력 `F = vₑ·ṁ` ↔ 회전수 kcat, `Vmax = kcat·[E]₀`
- 지면/로켓 두 관점 시뮬레이터 ↔ 직접 곡선 / 이중역수 두 표현 + 억제제 효과

## GitHub Pages 로 배포하기

### 방법 A — GitHub Actions (권장, 이미 설정됨)
저장소에 `.github/workflows/deploy-pages.yml` 이 포함되어 있습니다.

1. 저장소 → **Settings → Pages**
2. **Build and deployment → Source** 를 **“GitHub Actions”** 로 선택
3. 이 브랜치(`main`/`master` 또는 작업 브랜치)에 푸시하면 자동 배포됩니다.
   배포가 끝나면 `https://<사용자명>.github.io/<저장소명>/` 에서 열립니다.

### 방법 B — 브랜치에서 바로 배포 (Actions 없이)
1. 저장소 → **Settings → Pages**
2. **Source: Deploy from a branch** → 브랜치 선택, 폴더는 **`/ (root)`**
3. 저장하면 잠시 후 위와 같은 URL 로 게시됩니다. (`index.html` 이 루트에 있어 그대로 동작)

> 로컬에서 확인만 하려면 `index.html` 을 브라우저로 그냥 열어도 됩니다. 답안과 진행 상황은
> 브라우저 `localStorage` 에 저장됩니다.

## 제출 방식 (백엔드 불필요)

`activities/enzyme-kinetics.html` 상단의 `CONFIG.submit.mode` 로 선택합니다. 기본값은 설정이 필요 없는 `"download"` 입니다.

| mode | 동작 | 설정 |
|------|------|------|
| `"download"` (기본) | 보고서를 JSON 파일로 저장 → 학생이 구글 클래스룸/이메일로 제출 | 없음 |
| `"googleForm"` | **구글 폼**으로 전송 → 연결된 스프레드시트에 자동 기록 (Apps Script 아님) | 폼 ID + 필드 매핑 |
| `"endpoint"` | Formspree / Cloudflare Worker 등 임의의 POST URL 로 전송 | URL 1개 |

**구글 폼으로 자동 수집하기** (스프레드시트에 쌓고 싶을 때, 서버 없이):
1. 구글 폼을 만들고 필요한 항목마다 **단답형** 질문을 추가합니다(모두 “필수 아님”).
   전체 답안을 통째로 저장하려면 `payload` 항목 하나만 있어도 됩니다.
2. 폼 미리보기에서 **페이지 소스 보기** → 각 질문의 `entry.XXXXXXX` 번호를 찾습니다.
3. `CONFIG.submit.mode = "googleForm"` 으로 바꾸고 `googleForm.formId` 와 `entries` 를 채웁니다.
   `formId` 는 폼 주소 `.../forms/d/e/<formId>/viewform` 의 가운데 부분입니다.
4. 폼 응답을 스프레드시트에 연결하면, 학생이 “제출”할 때마다 자동으로 한 줄씩 쌓입니다.

인쇄(PDF 저장)와 JSON 다운로드는 어떤 모드에서든 항상 가능합니다.

## 교사 대시보드 (`teacher.html`)

학생 제출을 **반별로 누적·집계**해서 보는 교사용 화면입니다. 서버 없이 동작하며,
같은 사이트의 `…github.io/<저장소>/teacher.html` 로 함께 배포됩니다. (학생용 활동 `activities/enzyme-kinetics.html` 과 분리)

데이터를 넣는 방법 두 가지:

1. **파일 가져오기** (설정 불필요): 학생이 `download` 모드로 제출한 보고서 JSON들을 끌어다 놓으면
   누적 집계됩니다. 데이터는 **이 브라우저(localStorage)에만** 저장되어(외부 전송 없음) 다시 열어도 유지됩니다.
2. **구글 시트 CSV**: `googleForm` 제출을 쓰는 경우, 응답 시트를
   **파일 → 공유 → 웹에 게시 → 쉼표로 구분된 값(.csv)** 으로 게시한 URL을 넣으면 불러옵니다.
   응답에 `payload` 열(전체 JSON)이 있으면 문항별 분석까지, 없으면 이름·점수·서술형만 집계됩니다.
   ⚠️ 게시 링크는 공개되므로 학생 개인정보 취급에 유의하세요.

집계 화면:

- **개요**: 제출 인원, 유도확인·형성평가 반 평균, 서술형 작성률, **가장 정답률 낮은 문항 top 3**(피드백 지점)
- **학생 명단**: 정렬 가능한 표. 행을 클릭하면 그 학생의 예측·정오답·서술형 전문을 펼쳐 봄
- **문항 분석**: 문항별 정답률과 선택지 분포(어떤 오답을 골랐는지), 예측(사전 개념) 분포
- **서술형**: 학생별 서술형 답안 열람 + 키워드 점검 점수, **예시답안 열람 여부·시각**(새 보고서부터 표시, 예전 보고서도 그대로 읽힘)
- **CSV 내보내기 / 모두 지우기** (CSV에 '예시답안 열람' 열 포함)

## 서술형 피드백 (Step 07) — 키 없이 브라우저 안에서

외부 AI 호출이나 API 키 없이 동작합니다. 예전 버전이 학생 브라우저(`localStorage`)에 저장했던 키는 두 활동 페이지를 열 때 자동으로 지웁니다.

- **자가 점검(키워드 루브릭)**: 문항마다 점검 항목과 한국어·영어 표현(띄어쓰기 허용 정규식)을 두고, 찾은 항목 ✓ / 빠진 항목 △ + 안내 질문을 보여 줍니다.
  안내 질문은 정답 문장을 주지 않습니다. 서술 2는 '경쟁적'과 '비경쟁적'을 다룬 부분을 나눠 점검해, 두 억제제의 변화를 뒤바꿔 쓰면 ✓가 나오지 않습니다.
  - 서술 1: 낮은 [S]의 반응 차수 · 그 까닭(빈 활성 부위) · 높은 [S]의 속도·차수 · 효소 포화의 뜻 · 식(분모 근사) 근거 · Km의 의미
  - 서술 2: 경쟁적(결합 자리 · Km · Vmax · 높은 [S]로 극복) · 비경쟁적(결합 자리 · Vmax · Km) · 이중역수 그래프(경쟁적 / 비경쟁적의 절편·기울기)
  - 화면·보고서에 "키워드 기반 자동 점검 — 참고용이며 최종 평가는 선생님이 합니다"를 표시합니다.
- **예시 답안**: 답안이 60자 이상일 때만 열 수 있습니다. 열면 `essayReview.<문항>.exemplarViewed / exemplarViewedAt / exemplarLenAtView`가 보고서에 기록되고,
  교사 대시보드에 "예시답안 열람"으로 표시됩니다.
- **AI 도우미용 프롬프트 복사 (선택)**: 문항·점검 항목·학생 답안으로 "정답을 주지 말고 힌트로 피드백해 달라"는 한국어 프롬프트를 만들어 **클립보드에 복사만** 합니다
  (네트워크·키 없음, 복사가 막히면 선택 가능한 텍스트 상자로 대체). 학교에서 허용한 AI 도구에 붙여 넣어 쓰며, 끄려면 각 활동 파일 상단 `CONFIG.showPromptCopy` 를 `false` 로 바꾸세요.

## 커스터마이즈

- 목차: `index.html` 의 `CURRICULUM` 데이터(대단원 ▸ 중단원 ▸ 활동), 활동 유형은 `TYPE`, 활동 객체의 `sources`(출처) 필드
- 효소 워크북 문항: `activities/enzyme-kinetics.html` 의 `PREDICT`, `CHECK`, `QUIZ`, `ESSAY`, `DERIV` 배열 수정
- 서술형 자가 점검·예시 답안: `ESSAY_RUBRIC`(점검 항목·안내 질문·정규식), `EXEMPLAR`(모범답안), `MIN_EXEMPLAR_LEN`(기본 60자)
- 프롬프트 복사 버튼 숨기기: 각 활동 파일 상단 `CONFIG.showPromptCopy = false`
- 디자인 토큰: `<style>` 의 `:root` CSS 변수 (색상은 원본의 다크/시안 테마를 따름)
- 시뮬레이터 파라미터 범위: `S_MAX`, 슬라이더 `min/max`, `computeApparent()`(억제 모델)
